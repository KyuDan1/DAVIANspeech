# 평가 데이터 구성과 탐지 방법론

## 1. 문제 정의

현재 리더보드 성적은 ADS `0.68653`, CPS `0.98932`이다. CPS는 이미 매우
높으므로, 이번 개선의 중심은 음성·음악의 존재 여부보다 생성 여부를 판별하는
ADS로 잡았다.

ADS에서 확인해야 할 문제를 다음 세 가지로 나눴다.

1. 음성 딥페이크를 구분하지 못하는가?
2. 음성용 탐지기를 음악에 사용해서 음악 딥페이크를 구분하지 못하는가?
3. 음성과 음악이 섞이거나 순차적으로 등장할 때 파일 전체 판정이 무너지는가?

특히 기존 구조가 음성용 XLS-R 딥페이크 탐지기를 음악에도 그대로 사용한다는
점을 주요 병목으로 가정했다.

## 2. 진단 평가 데이터

로컬 평가 데이터는 음성 전용, 음악 전용, 혼합 오디오의 세 종류로 구성했다.
모든 샘플에는 대회 제출 형식의 `sample_submission.csv`와 정답 및 분석용
메타데이터를 담은 `truth.csv`가 함께 생성된다. 난수 시드를 고정해 동일한
평가셋을 반복해서 만들 수 있다.

### 2.1 음성 전용 평가셋

`scripts/build_eval_asvspoof.py`는 ASVspoof 2021 DF의 benchmark-ready
Parquet 데이터로 실제 음성과 생성 음성을 같은 수만큼 선택한다.

- 대회 범위와 같은 4~60초 샘플만 사용한다.
- 실제와 가짜 클래스를 균형 있게 구성한다.
- `VOICE_PRESENT=1`, `MUSIC_PRESENT=0`으로 지정한다.
- 음성이 가짜이면 파일 전체도 가짜로 지정한다.
- 코덱, 생성 공격, 보코더, 화자 정보를 보존한다.

이 평가에서는 음성 EER이 약 `0.0`이었다. 현재 XLS-R 음성 탐지기 자체가
주요 병목일 가능성은 낮다는 신호지만, ASVspoof가 모델의 학습 분포와 유사한
인도메인 데이터일 수 있으므로 대회 성능을 그대로 나타내는 수치는 아니다.

### 2.2 음악 전용 평가셋

`scripts/build_eval_musiccaps.py`는 MusicCaps의 실제 음악과 FakeMusicCaps의
생성 음악을 의미적으로 짝지어 구성한다. 같은 MusicCaps ID를 공유하는 실제와
생성 샘플을 한 쌍으로 사용하므로, 단순히 음악 내용이 다른 데서 생기는 차이를
줄일 수 있다.

포함한 생성 모델은 다음과 같다.

- AudioLDM2
- MusicGen Medium
- MusicLDM
- Mustango
- Stable Audio Open

실제와 가짜 양쪽 모두 모노 16kHz FLAC으로 동일하게 변환한다. 데이터 출처나
포맷 차이 대신 생성 흔적을 비교하기 위한 처리다.

음성용 XLS-R을 분리된 음악에 단독 적용한 초기 결과는 다음과 같았다.

- Music EER: 약 `0.34`
- File EER: 약 `0.46`

EER `0.5`가 무작위 판정에 가까우므로, 음악 탐지가 주요 병목이라는 근거로
판단했다.

### 2.3 음성·음악 혼합 평가셋

`scripts/build_eval_mixtures.py`는 앞에서 만든 음성과 음악을 조합한다.

- 동시 혼합: 음성과 음악이 같은 시간에 함께 재생된다.
- 순차 혼합: 음성 뒤에 음악이 이어지는 형태로 배치한다.
- 실제 음성/가짜 음성과 실제 음악/가짜 음악의 네 조합을 모두 포함한다.
- 음성과 음악의 상대 음량을 -6, 0, +6dB로 변화시킨다.

초기 혼합 평가 결과는 다음과 같았다.

- File EER: 약 `0.40`
- Voice EER: 약 `0.125`
- Music EER: 약 `0.475`

혼합 환경에서도 음성보다 음악 생성 여부 판정이 훨씬 약했다.

## 3. 진단 평가 방식

`src/evaluate_diagnostic.py`는 대회의 EER 및 ROC-AUC 계산식을 그대로 사용한다.
전체 결과뿐 아니라 데이터에 메타데이터가 있으면 다음 조건별 결과도 출력한다.

- 오디오 유형
- 데이터 출처
- 생성 모델
- 코덱
- 동시/순차 혼합 조건

이를 통해 총점만 비교하지 않고 어떤 유형에서 성능이 좋아지거나 나빠졌는지
확인할 수 있다.

## 4. 현재 탐지 방법론

현재 제출 파이프라인은 다음과 같다.

```text
입력 오디오
├── PANNs Cnn14
│   ├── VOICE_PRESENT_PROB
│   └── MUSIC_PRESENT_PROB
│
├── HTDemucs ── 음성 stem ── XLS-R-2B ── VOICE_FAKE_PROB
│
├── HTDemucs ── 음악 stem ── XLS-R-2B ─┐
│                                       ├── MUSIC_FAKE_PROB
└── 원본 전체 오디오 ── SONICS ────────┘
```

### 4.1 성분 존재 여부

PANNs Cnn14로 음성과 음악의 존재 확률을 계산한다. 기존 CPS가 `0.98932`로
높으므로 이 부분은 변경하지 않았다.

### 4.2 음원 분리

HTDemucs로 입력을 vocals stem과 나머지 음악 stem으로 분리한다. 평가 서버는
인터넷이 차단되어 있으므로 HTDemucs 체크포인트를 제출 ZIP 안에 포함하고
로컬 저장소에서만 불러온다.

### 4.3 음성 생성 탐지

음성 stem은 `nii-yamagishilab/xls-r-2b-anti-deepfake`로 판정한다. 원본
체크포인트는 fairseq 구조이므로 `src/xlsr_antideepfake.py`에서 Hugging Face
Wav2Vec2 구조로 엄격하게 매핑한다. 키 또는 텐서 크기가 일치하지 않으면 즉시
실패하도록 해 임의 초기화된 가중치로 조용히 실행되는 문제를 막는다.

원본 구현의 로짓 순서는 `[fake, real]`이므로 첫 번째 클래스의 softmax 값을
가짜 확률로 사용한다. 입력에는 원본 학습 방식과 같은 utterance 단위 정규화를
적용한다.

### 4.4 음악 생성 탐지

음악은 서로 다른 특성을 가진 두 탐지 결과를 결합한다.

```text
MUSIC_FAKE_PROB
= 0.75 × XLS-R(분리된 음악 stem)
+ 0.25 × SONICS(원본 전체 오디오)
```

SONICS는 음악 생성 탐지용 모델이다. 작은 로컬 평가셋에 과하게 맞추는 것을
피하기 위해 기존 XLS-R을 유지하면서 SONICS를 25%만 반영했다. 이 조합에서
음악 전용 평가셋의 Music EER은 약 `0.34`에서 `0.30`으로 개선됐다. 다만 혼합
오디오의 Music EER은 아직 좋지 않아 결합 비율이 최적인지는 추가 검증이
필요하다.

### 4.5 파일 전체 가짜 확률

대회 규칙상 음성 또는 음악 중 하나라도 가짜이면 파일 전체가 가짜다. 존재
확률을 가짜 확률에 직접 곱하면, 성분이 실제로 존재하지만 PANNs 점수가 낮은
경우 가짜 증거까지 약해지는 문제가 있었다.

현재는 존재 점수를 확률 보정값이 아닌 게이트로만 사용한다.

1. 존재 확률이 `0.3` 이상인 성분을 활성화한다.
2. 활성 성분의 가짜 확률 중 최댓값을 `FILE_FAKE_PROB`로 사용한다.
3. 두 성분 모두 기준보다 낮으면 존재 확률이 더 높은 성분의 가짜 확률을 쓴다.

이 변경 후 로컬 평가에서는 다음과 같은 변화가 있었다.

- 음악 전용 File EER: 약 `0.46 → 0.36`
- 혼합 File EER: 약 `0.40 → 0.35`
- 음성 전용 File EER: 약 `0.0` 유지

## 5. 제출 안정성 처리

- MP3, WAV, FLAC, AAC, M4A, OGG, OPUS, WMA 입력을 처리한다.
- 입력은 16kHz 모노로 변환한다.
- 긴 파일은 약 4초 구간으로 나누고 구간별 가짜 확률의 최댓값을 사용한다.
- 무음 또는 비어 있는 stem은 가짜 증거로 사용하지 않는다.
- L4 22.4GB에서 동작하도록 XLS-R 배치 크기를 1로 설정한다.
- 제출 크기를 줄이기 위해 XLS-R 체크포인트를 FP16으로 저장한다.
- PANNs, HTDemucs, XLS-R, SONICS 체크포인트를 제출물에 모두 포함한다.
- 추론 과정에서 외부 다운로드가 발생하지 않도록 오프라인 모드를 강제한다.
- 평가 서버의 기본 패키지를 사용하므로 제출용 `requirements.txt`에는 추가
  패키지를 설치하지 않는다.

현재 제출물은 약 4.2GB이며, 압축 무결성 검사와 단일 오디오 전체 추론,
`output/submission.csv` 생성 검증을 통과했다. 모델 독립 회귀 테스트는 총
11개가 통과했다.

## 6. 현재 평가셋의 한계

로컬 평가 결과는 절대적인 대회 예상 점수보다 변경 전후의 회귀 비교에 더
적합하다.

- ASVspoof는 XLS-R의 학습 분포와 유사할 수 있다.
- 한국어, 최신 TTS, voice conversion 및 전화 채널 음성이 충분하지 않다.
- 음악은 주로 10초이며 생성 모델 종류가 제한적이다.
- 보컬과 반주가 함께 있는 생성 노래가 충분하지 않다.
- 혼합셋은 자연 녹음이 아니라 인위적으로 합성했다.
- 전화 채널, 리버브, 잡음 및 다양한 손실 압축 조건이 부족하다.

따라서 로컬 수치가 좋아져도 실제 리더보드 개선은 제출을 통해 확인해야 한다.

## 7. 다음 실험 우선순위

### 7.1 현재 제출 결과 기록

현재 제출은 다음 설정을 사용한다.

- SONICS 가중치: `0.25`
- presence gate: `0.3`
- 파일 결합: 활성 성분 가짜 확률의 `max`
- 기준 커밋: `a0084cb`

제출 후 ADS, CPS와 최종 Score를 이전 결과와 함께 기록한다.

### 7.2 변경 요소 분리 검증

한 번에 여러 변경을 적용했기 때문에 아래 세 버전을 비교해야 한다.

| 버전 | 음악 탐지 | 파일 결합 |
| --- | --- | --- |
| A | XLS-R | 기존 방식 |
| B | XLS-R | presence gate + max |
| C | XLS-R + SONICS | presence gate + max |

A는 기존 제출이고 C는 현재 제출이다. 필요하면 B를 별도로 제출해 파일 결합과
음악 모델 중 어떤 변경이 실제로 효과가 있었는지 분리한다.

### 7.3 평가 데이터 확장

다음 조건을 고정 평가셋에 추가한다.

- MP3, AAC, Opus 등 다양한 손실 압축
- 8kHz 전화 채널 변환 후 16kHz 재표본화
- 잡음, 리버브 및 음량 변경
- 파일 일부에만 짧은 가짜 구간이 있는 경우
- 보컬과 반주가 함께 있는 실제·생성 노래
- 4~60초 길이 분포
- 모노와 스테레오 입력
- 실제 음성+가짜 음악, 가짜 음성+실제 음악 조합

### 7.4 음악 앙상블 비율 탐색

SONICS 비중 `0%, 25%, 50%, 75%, 100%`를 같은 평가셋에서 비교한다. 전체
EER만 보지 않고 음악 전용/혼합, 생성기, 코덱, 동시/순차 조건별 Music EER과
File EER을 함께 본다.

## 8. 현재 결론

로컬 진단에서는 음성보다 음악 딥페이크 탐지가 훨씬 약했고, 혼합 오디오의
음악 판정이 거의 무작위 수준이었다. 이를 개선하기 위해 음악 전용 SONICS를
추가하고 파일 전체 점수를 대회 규칙에 가까운 gate+max 방식으로 변경했다.

로컬에서는 일부 EER 개선을 확인했지만, 실제 대회 데이터에서의 개선 여부는
현재 제출의 ADS 결과를 통해 판단해야 한다.
