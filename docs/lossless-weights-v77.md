# v77: 검증한 FP32 가중치를 그대로 제출하기 위한 무손실 압축

## 목적

v73의 실제 `FrozenEncoderTokens`는 XLS-R를 기본 `dtype=torch.float32`로 불러온다.
기존 제출 빌더의 `copy_xlsr_fp16`을 그대로 적용하면 파일 크기만 바뀌는 것이 아니라
원래 가중치 값도 반올림된다. 따라서 v73의 동일 모델 배포라고 주장하려면 별도
출력 검증을 하거나 원래 바이트를 그대로 보존해야 한다.

이번 작업은 후자다. 모델의 architecture, tensor dtype, weight, 예측 규칙은 바꾸지 않는다.
기존 최고 모델이나 보호 평가 후보의 파일도 수정하지 않는다.

## 확인한 크기와 샘플 실험

| 원본 safetensors | 원본 bytes | 4MiB 중앙 샘플의 압축률 |
|---|---:|---:|
| XLS-R-2B | 8,651,845,440 | 0.84352 |
| SPEAR xlarge | 2,387,980,808 | 0.84363 |
| EAT large | 1,237,667,364 | 0.45171 |

각 파일 중앙의 샘플을 4바이트 단위 byte shuffle 후 표준 라이브러리 LZMA preset 6으로
압축했다. 이 표에서 전체 크기를 추정하면 약 9.87GB지만, 실제 압축 결과나 ZIP 크기는
아니다. 특히 10GB 제한에 가깝기 때문에 전체 실행을 완료하기 전에는 용량 통과라고
표시하지 않는다. 부가 head·코드·manifest·ZIP 메타데이터까지 최종적으로 포함해야 한다.

## 형식과 무결성

`src/lossless_weights_v77.py`는 원본을 최대 4MiB 블록으로 읽는다. 각 블록 안에서
바이트 위치를 재배열한 뒤 XZ로 압축하며, 모든 블록을 즉시 역변환해 원본과 비교한다.
4바이트 배수가 아닌 마지막 블록도 그대로 복원한다. tensor 파싱/양자화는 없다.

압축된 블록은 2,000,000,000 bytes 이하의 `.dw77` 멤버로 나눠 저장한다. 따라서
과거 업로드 검증기가 문제 삼았던 4GiB 초과 단일 ZIP 멤버를 만들 필요가 없다.
이 멤버는 이미 압축되어 있으므로 향후 ZIP에는 ZIP_STORED로 넣는 것을 전제로 한다.
실행 시 복원되는 native safetensors가 4GiB 이상인 것과 ZIP 멤버 크기는 구분한다.

manifest는 각 멤버의 SHA-256, 크기, 순서, 원본 offset과 전체 원본 SHA-256을 기록한다.
복원 시 이를 모두 확인하며 기존 파일을 덮어쓰지 않는다. 손상, 잘린 블록, 경로 순회,
중복 멤버, 비정상적인 블록 크기는 거부한다. 실패한 부분 출력은 진단용으로 남으며
완성 모델로 사용하면 안 된다. 전체 복원 SHA 확인을 통과해야만 완료로 인정한다.

4개 압축 thread를 쓰지만 대기 중인 블록을 8개로 제한해 전체 모델을 RAM에 쌓지 않는다.
오프라인 복원에는 Python 표준 라이브러리만 필요하며 GPU를 사용하지 않는다.
이는 실제 L4 평가 환경의 RAM·시간 검증을 대신하지 않는다.

## 실행 및 현재 범위

```bash
/usr/bin/python3 -m unittest tests/test_lossless_weights_v77.py -v
/usr/bin/python3 scripts/pack_lossless_weights_v77.py \
  --output reports/lossless_weights_v77/full --workers 4
```

무작위 바이트/마지막 블록, 여러 멤버의 전체 복원, 덮어쓰기 거부, 손상·경로 검사를
포함한 테스트 4개가 통과했다. 전체 인코더 세 개의 압축 및 디스크 복원 검증은
`reports/lossless_weights_v77/full/report.json`의 `status=complete`로 확인해야 한다.
진행 중인 멤버 파일이나 frozen.json만으로 완료를 판정하지 않는다.

`verified_restore/`의 큰 원본 파일들은 연구용 검증 산출물이므로 제출 ZIP에 넣지 않는다.
완료 보고서가 있더라도 이것은 가중치 준비 완료일 뿐, 최종 ZIP 생성·설치 검증·실제
서버 추론·리더보드 성능 확인 완료를 의미하지 않는다. 자동 제출하지 않는다.

## 전체 압축·복원 완료 결과

2026-09-05 전체 실행이 종료됐다. 원본 파일을 디스크에 다시 복원한 뒤 세 모델 모두
전체 SHA-256 일치를 확인했다.

| 모델 | 전체 압축 bytes | 복원 시간, 연구 서버 |
|---|---:|---:|
| XLS-R | 7,299,154,280 | 91.26초 |
| SPEAR | 2,012,994,216 | 25.43초 |
| EAT | 544,092,360 | 15.11초 |
| 합계 | **9,856,240,856** | **131.81초** |

원본 합계는 12,277,493,612 bytes이며, 십진수 10GB까지 남은 공간은
143,759,144 bytes다. 압축과 실제 디스크 복원 검증을 합쳐 941.67초가 걸렸다.
이 시간은 로컬 CPU/스토리지 측정이고 L4 서버의 6 vCPU 실행 시간을 대신하지 않는다.
실제 ZIP에는 아직 code/head/manifest를 넣지 않았으므로 최종 ZIP 통과는 미검증이다.
