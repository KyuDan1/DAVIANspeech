# 네 칸 실험 코드 리뷰 결과 — 결론 대부분 철회

2026-09-01. 서브에이전트 4개(감사 3 + 판정 1)가 `mixtures4` 실험을 감사한 결과와,
내가 직접 재현한 검증.

```text
지적 36개  —  blocking 4 / serious 16 / minor 9 / none 7
감사 1 (생성)  conclusions-weakened
감사 2 (혼합)  conclusions-invalid
감사 3 (분석)  conclusions-weakened
```

산술 자체는 문제가 없었다. 14개 헤드라인 수치가 `cells4_scores.csv`에서 정확히
재현되고 EER 구현도 대회식이다. 무너진 것은 **그 수치가 무엇을 재고 있었는가**다.

## 1. 직접 재현한 결함

에이전트 주장을 믿지 않고 내 손으로 다시 계산했다. 셋 다 사실이었다.

### D5 — 길이가 곧 VOICE_FAKE 라벨

```text
진짜 음성 평균 12.35s / 가짜 8.26s
-DURATION 만으로   VOICE EER = 0.2800
탐지기(voice_stem_max) VOICE EER = 0.2633
```

**3줄짜리 길이 특징이 탐지기와 거의 동등하다.** MeloTTS/Audio8 합성물이 원본보다
짧게 나오는데 그대로 썼다. 이 셋의 voice 절대값은 진위가 아니라 길이를 재고 있다.

### D2 — 스펙트럴 플랫니스가 탐지기보다 낫다

```text
플랫니스만으로   MUSIC EER = 0.3133
탐지기(music_stem_max) = 0.3567
```

GTZAN(22.05kHz 원본)과 MusicGen(32kHz, 저역 편중)의 대역 차이가 라벨이 됐다.
판정 에이전트가 측정한 배경 풀 통계:

| | GTZAN(진짜) | MusicGen(가짜) |
| --- | ---: | ---: |
| 300–3400 Hz 대역 전력 | 0.401 | 0.110 |
| 95% 전력 rolloff | 3125 Hz | 664 Hz |
| 6 kHz 이상 전력 | 0.0058 | 0.0006 |
| 스펙트럴 플랫니스 중앙 | 0.01254 | 0.00119 |

같은 **광대역** SNR에서 가짜 배경은 대역 내 SNR이 `10·log10(0.401/0.110) = 5.6 dB`
유리하다. 이 셋의 음악 숫자는 생성 탐지를 재는 것이 아니다.

### D3 — 리더보드 비교가 성립하지 않는다

```text
로컬 0.3567   = XLS-R(stem) 단독
리더보드 0.3714 = 0.5 × XLS-R(stem) + 0.5 × ArtifactNet(원본)
```

**다른 지표다.** CSV에 ArtifactNet 컬럼이 없어 로컬에서 같은 값을 계산할 수조차
없다. 게다가 로컬 CI `[0.29, 0.43]`이 비교 대상인 두 리더보드 값을 **모두** 포함하고,
같은 로컬 지표가 가짜 음악 소스만 바꿔서 `0.4896 → 0.3567`로 움직인다 — 인용했던
"근접도" 0.015의 약 10배다.

그리고 이 셋은 **리더보드 결과를 알고 난 뒤에, 그것을 설명하는 가설을 구현하려고**
만들었다. 이미 제출 하나를 날린 그 실수의 반대 방향 판본이다.

## 2. 세 주장의 운명

| 어제 주장 | 판정 |
| --- | --- |
| stem이 원본보다 낫다 | **방향 유지.** 격차 0.106, 클러스터 CI `[0.018, 0.190]`, P(stem이 낫지 않음)=0.012. 보컬 있는 진짜 배경을 걸러도 0.3333/0.4833 |
| 진짜보컬+가짜음악에서 격차 최대 | **한계선.** 상호작용 CI `[0.007, 0.333]`, 하한이 0에서 0.003 |
| 그 이유가 "진짜 보컬이 가짜 반주를 가려서" | **철회.** 진짜 보컬일 때 `orig_max` 중앙값이 진짜 배경 0.0011 / 가짜 배경 0.0011로 평평하다. 가릴 것이 없었다 — 원본에 돌린 XLS-R은 음악 라벨에 반응하지 않는다 |
| 가짜 배경이 음성 판별을 쉽게 한다 | **철회.** 격차(CI `[0.097, 0.263]`)는 실재하나 원인이 "생성 여부"가 아니다. 저역 편중 배경을 분리기가 더 잘 벗겨낼 뿐이다 |
| logmeanexp가 절대 나빠지지 않는다 | **철회.** 내 표 안에서 이미 반증된다 — MUSIC/원본/진짜보컬 `0.5067 → 0.5467`. 세 델타 모두 CI가 0을 걸친다. 승리가 아니라 null 결과다 |
| 로컬이 처음으로 대회를 재현했다 | **철회.** D3 참조 |

## 3. 추가로 드러난 것

**D8 — PANNs 보컬 게이트가 사실상 작동하지 않는다.** 임계값 0.2에서 `pop_ai`의
완전한 노래 13곡 중 10곡을 통과시키고, 실제로 노래가 든 GTZAN 배경의 57%만 잡는다.
MusicGen 클립이 instrumental인 것은 **프롬프트 덕분이지 게이트 덕분이 아니다.**
그런데 `gen_fake_music.py` docstring은 게이트가 보장하는 것처럼 써 있다. 이번 배치는
결과적으로 무해했지만(HTDemucs 보컬 stem 에너지 중앙 0.0000 vs GTZAN 0.2625) 다음
배치에서 이것을 신뢰하면 안 된다.

**한쪽만 걸렀다.** 뽑힌 GTZAN 배경 48개 중 **60%가 보컬을 포함**한다. 가짜 쪽에만
검사를 걸고 진짜 쪽에는 안 걸었다. 진짜 배경을 `voice<0.2`로 거르면 real-music
voice EER이 `0.3200 → 0.2753`으로, 조잡한 부분 통제 하나가 격차의 27%를 먹는다.

**D6 — 배경 추출 위치가 주석과 어긋난다.** `build_mixtures.py:79`가 voice 루프
**안에서** 배경을 뽑아, 진짜음성 부분집합과 가짜음성 부분집합이 거의 겹치지 않는
배경을 쓴다(25개 중 2개만 공유). 바로 위 주석은 반대로 통제한다고 적혀 있다.
루프 밖으로 빼는 한 줄이면 되고, 주장 1이 걸려 있는 상호작용 CI가 좁아진다.

**D7 — 루프 이음매가 한쪽에만 생긴다.** MusicGen 클립은 전부 정확히 11.94초(길이
분산 0)라, 가짜 음악 혼합 84개는 배경을 타일링해 붙이고 진짜 음악 혼합은 0개다.
현재 수치를 좌우하진 않지만(이음매 있는 행 제거 시 0.3333 → 0.3300) 가장 중요한
칸에 공짜 라벨이 하나 놓여 있다.

## 4. 판정 에이전트가 감사 하나를 뒤집었다

혼합 감사는 "대역 차이는 너무 약해 무의미하다(EER 0.40~0.43)"고 했는데, 그것은
magnitude 기반 `spectral_rolloff`로 잰 값이었다. 판정 에이전트가 power spectrum으로
다시 재서 rolloff95 `3125 vs 664 Hz`, 완성된 혼합에서 플랫니스 EER `0.3100`을
보였다. 내가 재현한 `0.3133`과 일치한다.

반대로 **"라우드니스 통제는 필요 없다"는 유지됐다.** 셀 간 peak가
`0.900010 vs 0.900005`이고 SNR 스케일링이 정확한 전력비를 강제하므로 잡을 것이 없다.
scale-invariant dynamics 단서도 0.4933으로 무작위다.

## 5. 고쳐야 할 것

1. **길이 정규화** — 공통 길이 분포로 크롭. 이것 없이는 voice 절대값도, 풀링 비교도
   쓸 수 없다. 특히 logmeanexp는 주제가 길이 편향인데 길이가 라벨과 상관된 셋에서
   평가됐다.
2. **대역 통제** — 양쪽 배경을 같은 샘플레이트로 올린 뒤 동일한 MP3 1세대 통과.
3. **양쪽에 같은 보컬 검사** — GTZAN도 걸러야 하고, 게이트는 PANNs가 아니라 HTDemucs
   보컬 stem 에너지(>0.02 기각)로. PANNs는 사전 필터로만.
4. **배경 추출을 voice 루프 밖으로** — 한 줄.
5. **자명한 특징 게이트를 상시 검사로** — 플랫니스·길이 같은 3줄짜리가 탐지기와
   비등하면 그 셋은 아직 쓸 수 없다. 매 빌드마다 자동으로 확인한다.

## 6. 지금 유효한 것

**stem > 원본이라는 방향 하나뿐이다.** 메커니즘 설명은 틀렸고 숫자는 인용할 수 없다.
어제 `-0.0418`을 되돌리는 근거로는 여전히 쓸 수 있지만 그 이상은 아니다.

`complike_v2`도 같은 결함(길이·대역·한쪽만 거른 보컬 검사)을 물려받았으므로
재채점 전에 위 다섯 가지를 고쳐야 한다.
