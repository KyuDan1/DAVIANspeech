# v71: 짧은 가짜 구간을 직접 학습하는 비교 실험

## 해결하려는 문제

v70 합성 스트레스 검사에서 EAT adapted의 60초 동시 혼합은 File EER 0.1722였지만,
2초 가짜 음성 삽입의 Voice EER은 0.4833, 2초 가짜 음악 삽입의 Music EER은
0.4833이었다. 깨끗한 채널에서도 문제가 있어 전화 router만으로 설명할 수 없다.
이는 **우리 합성 검사에서 드러난 실패**이며 실제 비공개 평가셋의 구성이나 원인을
확정하는 근거는 아니다. 출처와 제약은 `long-component-stress-v70.md` 참고.

가설: 파일 전체 정답만으로 학습하면 대부분의 진짜 구간에 묻힌 짧은 가짜 성분을
찾는 학습 신호가 부족할 수 있다. 분리 모델을 추가하기보다 원본 오디오의 시간별
표현에 정확한 삽입 구간 정답을 주는 방법을 비교한다.

## 관련 연구와 적용 범위

[PartialSpoof (Zhang et al.)](https://arxiv.org/abs/2204.05177)는 짧은 생성 음성을
진짜 발화에 삽입하는 문제에서 SSL 표현과 발화/다중 해상도 구간 정답의 공동 학습을
다룬다. [저자 코드](https://github.com/nii-yamagishilab/PartialSpoof/tree/main/03multireso)도
공개되어 있다. v71은 그 문제 설정을 음성·음악의 두 성분으로 확장한 별도 구현이며,
논문의 전체 구조나 성능을 재현한 실험이 아니다.

[Liu et al. (2024)](https://arxiv.org/html/2406.02483v1)은 PartialSpoof로 학습한
탐지기가 가짜 내부보다 접합 전이 구간에 크게 의존할 수 있음을 Grad-CAM/정량
분석으로 보였다. 따라서 이 대회에서는 편집 경계 검출 자체를 최종 목표로 삼지 않는다.
진짜 대조군에도 다른 진짜 원천의 접합을 넣고 경계 bin 손실을 제외한다. 이것으로
모든 편집 단서 의존성이 사라진다고 주장하지 않으며, 성분 내부에서의 진위 판별과
새 생성기/채널 일반화는 별도 검증이 필요하다.

## 비교 방법

| 항목 | file_only | dense_supervised |
|---|---|---|
| 인코더 | 학습 완료 EAT adapted, 완전히 고정 | 동일 인코더 계산 공유 |
| 입력·원천·샘플 순서 | 동일 | 동일 |
| 초기 head 파라미터 | 기존 EAT head로 초기화 | bit-exact 동일 초기화 |
| 시간 해상도 | 0.16초, 64 time × 8 frequency 패치 유지 | 동일 |
| 학습 손실 | 파일의 5개 정답 | 파일 정답 + 0.5 × 시간별 정답 손실 |
| 파일 내 집계 | 고정 temperature 5 logmeanexp | 동일 |

주파수 토큰은 시간별 head 내부에서 처리하며 시간축을 먼저 평균하지 않는다.
각 파일 안의 모든 10.24초 window를 사용한다. 서로 다른 파일의 통계·예측은
섞지 않는다. 시간별 fake 손실은 해당 성분이 존재할 때만 계산하고, 진짜/가짜
bin 수 차이에 짧은 가짜 구간이 묻히지 않도록 두 클래스의 평균 손실을 균등 반영한다.
경계 ±0.08초는 무시한다. 시간 정답은 원천 배치 정보이지 실제 발성/VAD 정답은 아니다.
인코더의 self-attention은 넓은 문맥을 보므로 패치 위치가 완전히 국소적인 표현이라는
가정도 하지 않는다.

## 학습 데이터와 누수 방지

기존 strict train 18,738개와 development 4,577개 분할을 유지한다.
원천 catalog에는 strict train에 실제 등장하는 **원본 단독 성분**만 넣는다.
development, locked, OOD/Suno, stress, 폐기된 평가 자료의 원천·그룹과 겹치는지
메타데이터로 검사한다. v70 오디오나 원천 catalog는 학습에 사용하지 않는다.

확보된 원천은 진짜 음성 546, 가짜 음성 554, 진짜 음악 197, 가짜 음악 470개다.
혼합/보컬 등 단독 성분 조건을 만족하지 않는 218개는 제외했다. 이 의미 분류는
기존 원천 truth에 의존하며 새로 모든 파일을 사람이 청취한 것은 아니다.

학습 draw의 50%는 기존 strict train, 50%는 위 학습 원천으로 온라인 합성한다.

- 길이: 4/8/16/32/60초. 짧은 원천을 이어 붙이거나 반복하므로 자연스러운 실제
  60초 전화 통화를 수집한 것과는 다르다.
- 구성: 단독 음성/음악, 동시 혼합, 두 순서의 순차 혼합, 음성/음악 내부의 부분 가짜.
- 부분 가짜: 같은 성분의 진짜 배경에 0.5/1/2/4초 가짜 삽입. 음성이 잠깐 있고
  나머지는 음악만 있는 예와 구별된다. 짧은 파일에서는 삽입 길이를 절반 이하로 제한한다.
- 진짜 대조군도 **다른 원천 그룹**의 진짜를 같은 위치·길이·fade 방식으로 삽입한다.
  진짜끼리의 목소리/곡 전환도 포함해 단순 원천 전환을 가짜 단서로 쓰지 않게 한다. 가짜 여부만
  편집 경계로 구별하지 못하게 하려는 통제이며 모든 합성 편향을 제거한다는 보장은 없다.
- 진진/진가/가진/가가를 모두 생성하고 SNR은 −10/−5/0/+5/+10 dB에서 선택한다.
- 최종 혼합 후 clean/G.711/G.722/Opus NB/G.711→Opus를 적용한다.
- 생성기 family를 균등 선택한 뒤 그 family의 학습 원천을 선택한다.

각 draw의 원천 ID·그룹·실제 파일 SHA256·구간·채널·seed 위치를 기록한다.
catalog 자체와 원천 truth의 체크섬, 보호 데이터와의 identity 분리는 학습 시작 때
다시 검증한다. SHA256은 읽은 payload의 재현성 확인이며 모든 평가 오디오와의
파형 유사도 중복 탐지를 수행했다는 뜻은 아니다.

## 계산 자원과 선택 규칙

한 GPU에 두 head를 함께 올리고 가장 비싼 frozen encoder forward를 공유한다.
다른 사용자의 GPU 작업은 중단하지 않는다. 메모리 여유만으로 병렬화를 무작정
늘리지 않고 GPU 사용률과 I/O 대기, 실제 처리 시간을 함께 본다.

각 방식은 4,096 draws × 6 epochs, batch 4. 2/4/6 epoch에 기존 development만
평가하여 사전에 고정된 `0.5 × pooled ADS + 0.5 × domain-macro ADS`로 선택한다.
v70, locked 평가, Suno 평가로 checkpoint·집계 온도·가중치를 선택하지 않는다.
원본 EAT head와 달리 시간별 읽기/집계 구조가 바뀌므로 기존 global EAT와는 여러
차이가 있다. **file_only 대 dense_supervised 쌍에서만 손실 하나의 ablation**이다.

학습 전 고정 TRAIN 원천 16개로 encoder chunk 2/8/16을 비교했다. B200에서
반복 3회의 중앙값은 각각 0.11870/0.06800/0.06079초, peak allocated는
1,325/1,731/2,083MiB였다. 이 16개에서 확률 차이는 0이었다. 최종 encoder chunk를
16으로 설정한다(optimizer의 파일 batch 4는 유지). 파일 디코딩/학습/전체 설치 시간은
포함하지 않는 작은 메모리·처리량 검사이며, 전체 학습이나 L4 제출이 2배 빨라진다는
뜻은 아니다. 같은 GPU에 별도 독립성 검사도 실행한 환경이므로 전용 GPU의 엄밀한
성능 벤치마크로 간주하지 않는다.

## 현재 상태

원천 catalog 생성과 관련 59개 단위 검사(5개 실제 codec 왕복 포함), `smoke_v2/` CUDA 학습/8파일 평가가
통과했다. smoke의 GPU peak allocated는 약 1.56GB였다. 해당 8개 파일을 개별
추론한 확률과 저장 값 차이는 최대 2.71e-8, 순서를 뒤집은 결과는 bit-exact였다.
smoke는 정확도 평가가 아니므로 성능 수치를 제시하지 않는다.
아직 v71 전체 학습 성능 결과나 제출 후보 승격은 없다. 이 실험은 자동 제출하지
않는다. 결과 파일은 `reports/dense_component_v71/`에 저장한다.

`full/` 전체 paired 학습 작업을 GPU 0에 실행했다. 최종 데이터 통제를 반영하고
encoder chunk 16을 사용한다. 완료 여부는 `full/completed.json`으로 판단해야 하며,
이 파일이 없으면 학습 완료나 최종 checkpoint 확보를 주장하지 않는다.

첫 epoch의 실제 trace에서 4,096 draws 중 온라인 합성은 2,002개였다. 7개 layout은
각각 270~313개, 5개 channel은 388~415개, 5개 길이는 388~413개로 생성되었다.
이는 학습 입력 검증이며 평가 데이터의 실제 분포를 추정한 수치가 아니다.

2/6 epoch 중간 평가(개발 4,577개, 아직 최종 선택 아님):

| 방법 | File EER | Voice EER | Music EER | ADS |
|---|---:|---:|---:|---:|
| file_only | 0.17309 | 0.21862 | 0.14363 | 0.82664 |
| dense_supervised | 0.18740 | 0.22361 | 0.14363 | 0.81849 |

이 시점에서는 dense 정답이 우세하지 않다. 학습 손실에는 항목 수 차이가 있어
두 방식의 손실 크기를 직접 비교하지 않는다. 6 epoch를 예정대로 완료한다.

4/6 epoch에서도 file_only의 ADS 0.831881, dense_supervised의 ADS 0.826880으로
아직 dense 정답 추가가 우세하지 않다. 두 방식 모두 2 epoch보다 pooled ADS는
올랐지만, 실제 제출 성능 개선 또는 최종 모델 선택으로 해석하지 않는다.

## 완료 결과: 전체 교체는 불리하지만 Music 전문가는 유망

6 epochs를 완료했다(약 2,076초, 이 실행 환경의 학습/평가 포함 시간).
사전 기준으로 두 방식 모두 epoch 4가 선택됐다. 4,577개 전체의 독립 파일 추론에서
File/Voice/Music EER과 ADS는 저장된 평가와 같았다. 전체 trace, 체크섬, checkpoint
선택 검증도 통과했다. 결과: `reports/dense_component_v71/final_audit/`.

현재 최고 제출의 동일한 codec 개발 600개에서 **해당 열만 교체**한 결과:

| 변경 | File EER | Voice EER | Music EER | ADS |
|---|---:|---:|---:|---:|
| 기존 최고 제출 앵커 | 0.23333 | 0.20667 | 0.25333 | 0.76600 |
| file_only의 File만 사용 | 0.28000 | 0.20667 | 0.25333 | 0.74267 |
| dense_supervised의 Voice만 사용 | 0.23333 | 0.32667 | 0.25333 | 0.74200 |
| file_only의 Music만 사용 | 0.23333 | 0.20667 | 0.17333 | 0.79000 |
| dense_supervised의 Music만 사용 | 0.23333 | 0.20667 | 0.16333 | 0.79300 |

다른 네 출력은 정확히 유지했다. 따라서 새 모델 전체를 교체하거나 음성 전문가로
쓰는 방향은 이 비교에서 지지되지 않는다. **음악 전용 후보로서의 이득**은 확인된다.
다만 600개는 120개 기본 혼합의 5개 채널 버전이므로 600개 독립 원천은 아니다.

| Music 모델 | clean | G.711 | G.722 | Opus NB | G.711→Opus |
|---|---:|---:|---:|---:|---:|
| parent global EAT | 0.06667 | 0.11667 | 0.08333 | 0.28333 | 0.33333 |
| file_only temporal | 0.06667 | 0.11667 | 0.08333 | 0.23333 | 0.31667 |
| dense_supervised temporal | 0.06667 | 0.08333 | 0.08333 | 0.21667 | 0.28333 |

기존 제출 앵커 대비 Music EER 차이의 기본 혼합 단위 paired bootstrap
(500회, 기술적 95% 구간)는 file_only −0.13088~−0.02746,
dense_supervised −0.14500~−0.03413이었다. 반복 사용한 development에서의 기술적
불확실성이지 모델 선택 편향이 보정된 검증이나 새 생성기 일반화 증명은 아니다.

중요하게도 dense 손실의 **순수 추가 효과**는 0.17333→0.16333의 1pp다.
두 v71 head를 직접 비교한 Music EER 차이의 동일한 paired bootstrap 구간은
−0.04000~+0.01754로 0을 포함했다. 따라서 이 1pp를 확실한 개선으로 단정하지 않는다.
앵커 대비 9pp 전체를 시간별 손실 덕분이라고 해석하면 안 된다. 학습 입력과
시간별 head 구조가 바뀐 효과는 file_only에도 있다. 실제 비공개 점수 상승은
아직 확인하지 않았으며 자동 제출하지 않았다.

완료 후 `scripts/rescore_dense_component_pair_v71.py`로 두 선택 head의 전체
development를 파일 단위로 재평가한다. 이때도 한 파일의 encoder 계산을 두 head가
공유하지만, 서로 다른 파일을 한 forward에 넣지 않는다.
`scripts/finalize_dense_component_v71.py`는 전체 epoch trace·snapshot·checkpoint
선택과 개별 추론을 검증한 뒤 성분·채널별 지표 및 앵커의 단일 열 교체 진단을 만든다.
서로 다른 열을 동시에 바꾸거나 혼합 가중치를 탐색하지 않는다.

첫 `smoke/` 작업은 source audit까지 통과했으나, 위의 다른 진짜 원천 대조군을
반영하기 위해 학습 전에 의도적으로 중단했다. 오류·학습 결과로 집계하지 않는다.
`smoke_v2` 이후에는 원천 이어 붙이기의 음성 piece 길이를 같은 draw 안의
진짜/가짜/진짜 대조군에 동일하게 적용하도록 보강했다. 인증 클래스에 따른 반복
주기 차이를 줄이기 위한 수정이며, 최종 학습 전 데이터 검사에 포함한다.
