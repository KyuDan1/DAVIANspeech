# 목표 0.80 까지의 계획

Score `0.80`에 필요한 ADS는 `0.778964`. 현재 `0.7083888889`이므로 격차는
**`+0.070575`**다.

## 1. 격차를 어디서 메울 수 있나

프로브로 측정한 성분별 실측값이다.

| 항목 | EER | 가중치 | 가중 기여 | 이 항목만 0으로 만들면 |
| --- | ---: | ---: | ---: | ---: |
| File | 0.2741 | 0.5 | 0.1371 | ADS 0.8454 |
| Music | 0.3714 | 0.3 | 0.1114 | ADS 0.8198 |
| Voice | 0.2156 | 0.2 | 0.0431 | ADS 0.7515 |

**한 항목만으로는 도달하지 못한다.**

```text
Music 0.37 -> 0.20   ADS 0.7594  미달
File  0.27 -> 0.13   ADS 0.7784  미달 (그리고 File 은 직접 못 건드림)
Music -0.10 + Voice -0.10, File 이 따라서 -0.07   ADS 0.7934  도달
```

File은 성분들의 max로 파생되므로 직접 최적화 대상이 아니다. 실질적으로는
**Music과 Voice를 각각 0.10 안팎 낮추고 File이 따라오게 하는 것**이 유일한 경로다.

## 3. 빠진 두 칸을 만드는 방법

현재 커버리지는 절반이다.

| 보컬 | 음악 | 상태 | 소스 |
| --- | --- | --- | --- |
| 진짜 | 진짜 | 있음 (80) | FLEURS ko + GTZAN |
| 가짜 | 진짜 | 있음 (80) | MeloTTS/Audio8 + GTZAN |
| 진짜 | **가짜** | **없음** | FLEURS ko + **instrumental 생성 음악** |
| 가짜 | **가짜** | **없음** | MeloTTS/Audio8 + **instrumental 생성 음악** |

막힌 이유는 하나다. 보유한 가짜 음악(SONICS, AI 팝 13곡)이 **전부 보컬을 포함**해서,
배경음악으로 깔면 VOICE_FAKE 라벨이 모호해진다.

### 해법: instrumental 을 직접 생성한다

`facebook/musicgen-medium`, cc-by-nc-4.0, gated 아님. `transformers`의
`MusicgenForConditionalGeneration`으로 바로 돌아간다. 32kHz 출력, A100에서 12초
클립을 배치 8로 생성.

```bash
python scripts/gen_fake_music.py --out-dir korean_eval/fake_music \
    --count 300 --batch-size 8 --seconds 12 --panns-dir models/panns
```

프롬프트는 악기만 지정하고(`"solo piano ballad, gentle, no vocals"` 등 16종),
생성된 클립마다 PANNs 로 보컬 존재를 검사해 `voice > 0.2`면 버린다. 스모크
테스트에서는 8개 중 0개가 걸러졌다.

대안: **FakeMusicCaps**(AudioLDM2 / MusicGen / MusicLDM / Mustango /
Stable Audio Open 5종, instrumental). 생성기 다양성이 필요할 때 추가한다.

### 절대 하지 말 것

**AI 노래를 HTDemucs로 벗겨 instrumental 을 만드는 것.** 진짜 배경은 테스트 시점에
분리를 1회 거치는데 그런 가짜 배경은 2회를 거치게 된다. 탐지기가
"분리 잔재 = 가짜 음악"을 학습하게 되고, 이는 지금 Voice 브랜치를 망치고 있는
교란을 라벨로 심는 것과 같다. **분리 횟수는 네 칸 전부에서 동일해야 한다.**

### 라벨이 아닌 것으로 구분되지 않게 통제할 것

| 변수 | 위험 | 통제 |
| --- | --- | --- |
| 분리 횟수 | 위 참조 | 네이티브 생성만. 양쪽 0회 |
| 대역폭 | 생성기별 native SR 이 16k~44.1k 로 제각각이라 "16kHz 위 에너지 없음"이 공짜 라벨 | 전부 동일 샘플레이트로 맞춘 뒤 동일한 MP3 1세대 통과 |
| 라우드니스 | ArtifactNet 은 라우드니스를 본다. 정규화 전 진짜 0.485/가짜 0.923, 정규화 후 0.961/0.957 로 판별력 소멸 | `raw`와 정규화 두 벌을 만들어 양쪽 채점. 차이가 곧 레벨 의존도 |
| 보컬 혼입 | 빠진 칸이 생긴 원인 그 자체 | PANNs 검사, 진짜/가짜 양쪽에 동일 적용하고 기각률을 함께 보고 |
| 길이 | 생성기별 길이 분산이 0이면 그 자체가 지문 | 고정 길이 크롭 |

### SNR 격자

현재 `{+5, 0, -5}`는 **음성** 브랜치가 깨지는 영역(음악이 큼)만 본다. **음악**
브랜치가 깨지는 영역은 음악이 작을 때이므로 `{+20, +15, +10, +5, 0, -5}`로 넓힌다.

## 4. 이 실험이 답하는 것과 답하지 못하는 것

로컬 평가셋은 이미 리더보드 순위를 거꾸로 매긴 전력이 있다
([local-eval-validity.md](local-eval-validity.md)). 따라서 이 두 칸은
**대회 점수 예측용이 아니라 탐지기 진단용**이다.

답할 수 있는 것:

- 음악이 가짜일 때 우리 음성 판별이 어떻게 되는가 (지금 전혀 모른다)
- 리더보드에서 stem 이 원본보다 나았던 이유가 "진짜 보컬 + 가짜 반주" 때문인가.
  그런 파일은 가짜 흔적이 반주에 있으므로 분리해야 보이고 원본에서는 진짜 보컬에
  가려진다. 우리 데이터에 그 조합이 없어 지금까지 검증할 수 없었다.

답할 수 없는 것:

- 어떤 구성이 리더보드에서 더 나은가. 그것은 제출로만 확인한다.
