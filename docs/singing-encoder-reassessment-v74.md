# 발화와 보컬을 같은 문제로 취급하면 안 되는 이유

## 로컬 실험이 바꾼 우선순위

v73은 개발 전체 ADS 0.87554, 실제 제출 앵커를 새로 실행한 codec 개발 비교에서
0.76667→0.82856을 보였다. 그러나 보호된 Suno 13클립의 음성 존재 확률 중앙값은
0.06273, 음성 Fake 확률 중앙값은 0.30290이었다. File/Music은 모두 0.5 이상이라
파일 Fake 검출만 보면 이 약점이 가려진다. 자세한 한계는
`docs/suno-frozen-v73-audit.md`를 따른다.

따라서 다음 연구 질문은 단순히 더 큰 encoder인가가 아니라 **발화/노래가 모두
음성이라는 라벨 정의를 학습과 평가가 실제로 반영하는가**이다. 이는 현재 결과에서
세운 가설이며, 노래 도메인 부족이 유일한 원인이라고 확정한 것은 아니다.

## 연구 결과에서 가져올 것

### 1. 발화 탐지기를 그대로 가져오는 것은 충분하지 않다

SingFake 연구는 발화로 학습한 탐지기의 노래 도메인 성능 저하와, 노래 혼합 또는
보컬로 학습했을 때의 개선을 보고했다. 보컬과 발화의 음향적 차이뿐 아니라 반주,
미지 가수, 언어, 통신 codec도 일반화 문제다. 따라서 XLS-R가 발화에서 좋다는
근거를 합성 보컬 전체에 확대하지 않는다.
[SingFake, ICASSP 2024](https://arxiv.org/abs/2309.07525)

### 2. WavLM은 보컬 학습 조건에서 다시 검토할 근거가 있다

XWSB는 XLS-R 0.3B와 WavLM Large를 각자의 SLS head와 함께 보컬 데이터에서
학습한다. SLS는 transformer 여러 층을 입력에 따라 가중하고, 마지막에 두 시스템을
결합한다. 표 2의 전체 EER은 XLS-R 5.12%, WavLM 4.92%, 결합 4.45%다.
초록의 2.32%는 표에서는 **ACESinger 제외** 결과이므로 전체 생성기 성적으로
소개하면 안 된다. 우리의 3개 층 frozen readout 결과와 같은 학습 조건이 아니다.
[XWSB 본문·표 2](https://arxiv.org/html/2409.18558v1)

다른 CtrSVDD 연구의 SEA는 층별 가중을 입력에 맞게 조절하고 RawBoost와 조합한다.
표에서 WavLM SEA 단일 모델은 A09–A13 EER 2.70%, A14 포함 전체는 5.66%다.
최종 ensemble의 1.79% 역시 A14 제외이며, 포함 시 4.76%이고 일부 개선은
post-evaluation 단계에서 얻었다. 보고된 최고 숫자를 우리 대회 예상 EER로 쓰지 않는다.
[Speech Foundation Model Ensembles, 표 2–3](https://arxiv.org/html/2409.02302v1)

### 3. 음악의 규칙성보다 반주에 흔들리지 않는 보컬 증거가 먼저다

2025년 SingFake 분석에서는 원래 반주 대신 무관한 음악/잡음을 넣어도 비슷하거나
더 나은 결과를 얻었다. 반주는 그 실험에서 주로 augmentation 역할을 했고,
분류기는 보컬의 저주파 단서에 많이 의존했다. 모든 모델에서 반주가 항상 도움이
된 것은 아니며, 평가 범위도 T01이었다. 이 결과는 리듬이 전형적이라는 이유만으로
Fake를 정하기보다 보컬·반주 조합에 불변인 증거를 학습하자는 방향을 지지한다.
Suno처럼 반주 자체도 생성된 경우나 전화 대역으로의 일반화를 입증하지는 않는다.
[How Does Instrumental Music Help SingFake Detection?](https://arxiv.org/html/2509.14675v1)

## 다음 실험의 설계 원칙

1. 지금 고정한 v73과 실제 앵커의 긴 음성 검증은 완료한다. Suno 결과를 보고
   진행 중인 후보/결합식을 바꾸지 않는다.
2. 추가 학습 전에 발화, 보컬 단독, 실제 보컬+실제 반주, 합성 보컬+실제 반주,
   실제 보컬+합성 반주, 둘 다 합성인 곡의 원천·라벨·라이선스를 구분한다.
   음원 전체가 Fake라는 정보만으로 두 성분 라벨을 자동 부여하지 않는다.
3. 새 학습에서는 발화/보컬을 함께 Voice로 다루고, 기존 EAT 음악 전문가와
   Voice 전문가를 유지한다. WavLM의 입력별 층 결합 및 제한된 encoder 학습은
   같은 데이터의 frozen readout 대조군과 비교한다. 곧바로 모델 수를 늘리지 않는다.
4. Presence는 별도의 의미 인식 문제다. 사전학습 의미 표현이 authenticity 학습 중
   손상되거나 학습 라벨 편향을 따라가는지 확인한다. 확률을 File에 곱할 때에는
   순위 지표뿐 아니라 개발 자료에서의 확률 보정도 확인한다.
5. 보컬/반주 혼합은 허용된 TRAIN 원천끼리만 만들고, 원곡·가수·생성기를 기준으로
   나눈 새 평가 자료를 먼저 보호한다. 기존 Suno 13개에 임계값/가중치를 맞추지 않는다.

이는 다음 실험 후보의 설계 원칙이며 새 학습을 완료했다는 보고가 아니다.

## 데이터 후보와 이용 조건

CtrSVDD는 14개 SVS/SVC 방법과 원천/생성기 구분이 있는 보컬 데이터 후보다.
논문에는 CC BY-NC-ND 4.0으로 명시되어 있다. 비영리 허용만 확인하고 파생 혼합물
공유나 모델 배포까지 자동 허용된다고 해석하지 않는다. 실제 사용할 배포본과 원천의
조건, 파생물·가중치 배포 조건을 확인한 후 채택한다. 이 조사에서 새 음원이나
checkpoint를 다운로드하거나 학습에 편입하지 않았다.
[CtrSVDD 데이터 설계 논문](https://arxiv.org/html/2406.02438v2)

보컬 합성이 약하다는 진단은 음악 전체의 AI 여부를 포기하자는 뜻도, diffusion 분리가
무조건 불가능하다는 결론도 아니다. 이번 후보는 분리를 하지 않는다. 먼저 원본 입력의
성분별 문제를 구분하고, 새 자료에서 실제로 개선되는지를 확인하는 것이 목적이다.
