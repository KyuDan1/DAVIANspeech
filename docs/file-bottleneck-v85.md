# v85: 실제 0.85 목표를 위한 File 병목 진단

현재 공식 최고는 0.7774307884이고 목표는 **실제 제출 0.85 이상**이다.
이 문서의 새 결과는 공개 진단 데이터 결과이며 공식 점수 개선이 아니다.

## 1. 어느 혼합이 어려운가

동일한 실제 음성+실제 음악(RR)을 음성만 가짜(FR), 음악만 가짜(RF),
둘 다 가짜(FF)와 각각 비교했다. RR 150개, 각 가짜 조건 150개이고
5개 채널/3개 시간 배치가 포함된다. 서로 다른 pair의 RR은 같은 표본이다.

| File 비교 | 실제 재실행 anchor | v73 성분 조합 |
|---|---:|---:|
| RR vs FR | 26.00% | 12.67% |
| RR vs RF | 26.67% | 22.00% |
| RR vs FF | 17.33% | 12.67% |

이 개발 bank에서 **한 성분만 가짜인 두 경우가 모두 어렵다**.
FR만이 유일한 문제라고 할 수 없다. 실제 평가셋의 조건별 오류는 공개되지 않았으므로
이 비율/난이도를 공식 데이터의 사실로 옮기지 않는다.
0.5 고정 threshold에서 anchor RR 오탐은 70.67%였지만 EER는 threshold 독립 평가다.
따라서 단순 threshold 변경으로 공식 EER가 개선된다고 주장하지 않는다.

## 2. 현재 성분 확률을 재결합하면 해결되는가 — 아니오

기존 모델을 재학습하지 않고 File만 두 고정 규칙으로 재계산했다.
`v=VoiceFake*VoicePresent`, `m=MusicFake*MusicPresent`.
규칙은 noisy-OR `1-(1-v)*(1-m)`와 `max(v,m)`이며 가중치 탐색은 하지 않았다.

| 데이터 | 현재 File | noisy-OR | max |
|---|---:|---:|---:|
| codec-mixed 600개 | 23.33% | 32.00% | 32.56% |
| 긴 부분 가짜 uniform 720개 | 41.39% | 44.17% | 43.33% |
| 긴 부분 가짜 fixed 2,160개 | 31.20% | 41.11% | 40.93% |

세 bank에서 모두 악화했다. 따라서 **현재 성분 출력의 단순 재결합 후보는 탈락**이다.
이것이 모든 확률 결합 방식의 불가능성을 증명하지는 않지만, 별도 File 모델이
지금 성분 확률만으로 복구되지 않는 유효한 정보를 가지고 있음을 시사한다.

## 3. 기존 EAT의 직접 학습된 File head는 쓸 만한가 — 현재 교체 불가

v73의 File은 직접 File head가 아니라 XLSR/SPEAR Voice와 EAT Music/Presence의
조합이었다. 이번에는 기존 EAT checkpoint의 **실제 File head 출력**을 직접 추론했다.
같은 가중치로 2,880개 파일을 GPU 6의 네 독립 worker에서 나눠 계산했고,
worker별 720개, 모델 로드 후 약 78–81초였다. 입력 SHA를 읽기 전/후 확인했다.

| 데이터 | 현재 File | EAT 직접 File |
|---|---:|---:|
| codec-mixed 600개 (기존 native cache) | 23.33% | 24.67% |
| 긴 부분 가짜 uniform 720개 (새 추론) | 41.39% | 42.50% |
| 긴 부분 가짜 fixed 2,160개 (새 추론) | 31.20% | 43.80% |

직접 File head도 현재 모델을 대체하지 못한다. 단지 v73의 마지막 OR 계산만
고치는 것으로 긴 파일 문제가 해결됐다고 볼 근거는 없다.
EAT 직접 File의 일반 개발 4,577개 EER는 16.89%지만 이 수치만 보고 승격하지 않는다.

## 다음 실험이 해결해야 할 조건

- 현재 Voice/Music 확률 재결합이 아니라, **File에 직접 유효한 원본 오디오 증거**를 개선해야 한다.
- FR과 RF를 모두 다루고, FF 개선만으로 성공으로 판정하지 않는다.
- 긴 부분 가짜 검출 개선과 일반 실제 오디오 오탐 억제를 함께 검증한다.
- 기존 v60 WPT 재학습, v71/v72 EAT dense/adapter, v80 local Voice 결과와
  차이를 명시한다. 이미 실패한 구조를 새 방법인 것처럼 재실행하지 않는다.
- 보호 eval과 Suno는 학습에 넣지 않는다. 위 bank는 이미 노출됐으므로 새로운 blind로
  부르거나 이곳에서 threshold/혼합 비중을 최적화하지 않는다.
