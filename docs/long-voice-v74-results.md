# v74 보호 평가 결과: v73 전체 교체 후보는 승격하지 않음

## 결론

v73은 짧은 개발셋에서 높았지만, 긴 실제 음성 중 짧은 가짜 구간을 검출하는 보호
평가의 사전 기준을 통과하지 못했다. **최고 제출을 v73으로 교체하거나 이 후보를
제출하지 않는다.** 기존 공식 최고 0.7774307884는 그대로이며, 아래는 대회 점수가 아니다.

## 고정한 비교의 전체 결과

학습에 쓰지 않은 원천 100개/20개 그룹에서 만든 30·45·60초 음성에 2초 실제/가짜
삽입 구간을 넣었다. 후보와 기존 최고 제출의 두 bank 전체 2,880파일을 각각 추론했다.
기존 모델은 SHA/CRC를 확인한 실제 `v50_v57m_challenger_v2.zip`의 실행 코드를 썼다.
중간 결과를 보고 모델·가중치·관문을 바꾸지 않았다.

| 평가 조건 | 파일 수 | 기존 File EER | v73 File EER | 기존 Voice EER | v73 Voice EER |
|---|---:|---:|---:|---:|---:|
| 무작위 삽입 위치, 주 평가 | 720 | 0.41389 | 0.37778 | 0.42500 | 0.38889 |
| 고정 초반·중간·후반, 별도 대조 | 2,160 | 0.31204 | 0.39537 | 0.39352 | 0.40370 |

무작위 위치의 File EER은 3.61%p 개선됐지만, 20개 원천 그룹을 resampling한
1,000회 bootstrap의 변화량 95% 구간은 **[-0.09865, +0.02500]**으로 0을 포함한다.
고정 위치는 8.33%p 악화했고 구간은 **[+0.02451, +0.15000]**이다. 고정 위치의
pooled/길이/채널 관문 7개가 모두 실패했다. 무작위 위치만 보고 통과로 바꾸지 않는다.

전화 열화만의 문제가 아니다. clean에서도 큰 악화가 있고, 양쪽 모델 모두 무작위
위치의 긴 파일에서는 약하다. 이 결과만으로 실제 비공개 평가가 이런 구성이라고
역추정하지 않는다.

## 해석과 다음 우선순위

v73의 통계 head는 10.24초 window의 토큰을 요약하고 파일의 window 점수를 결합한다.
기존 개발셋은 최장 20.2초이고 30–60초가 없다. 따라서 전역적인 성분 판별 개선이
짧은 국소 가짜 증거를 잘 찾는다는 뜻은 아니었다. 이번 결과는 **시간 구간을 다루는
학습·집계 방식**을 다음 주요 질문으로 만든다. 단, window 희석이 유일한 원인이라는
인과 증명은 아직 없다.

고정 위치 bank는 원래 기존 sparse WPT 창이 보는 위치에 맞춰 만들어진 covered-position
대조 조건이다. 이를 이유로 사전 관문을 없애지도, 무작위 bank와 임의 비율로 섞지도 않는다.
고정 위치에서 기존 모델의 장점이 확인됐고, 무작위 위치에서는 양쪽에 개선 여지가 크다.

다음 단계는 별도 TRAIN 원천에서 길이·삽입 위치·가짜 비율을 다양화하고, 구간 정답을
활용하는 짧은 창/시간축 Voice·File head를 개발 자료에서 비교하는 것이다. 전체 파일의
FAKE 라벨을 모든 창에 똑같이 붙이지 않는다. 이 보호 bank의 원천과 파생 음원은 계속
TRAIN에서 제외하고, 여기서 threshold나 모델 가중치를 반복 선택하지 않는다.

WavLM 제한 학습은 별도로 진행하되, encoder 변경만으로 이 시간축 문제가 해결됐다고
주장하지 않는다. 보컬/혼합 일반화도 이 음성 단독 bank로 검증한 것이 아니다.

근거: `reports/long_voice_v61/v73_one_shot/comparison/report.json`,
`paired_differences.csv`, `by_condition.csv`.
사전 계획은 수정하지 않고 `docs/long-voice-v74-evaluation.md`에 보존했다.
음악이 없고 presence 라벨이 상수여서 이 bank의 전체 ADS/CPS/Score는 정의되지 않는다.
